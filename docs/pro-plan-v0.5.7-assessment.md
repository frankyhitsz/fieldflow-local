# `pro-plan.md` 复核记录（v0.5.7）

> 这是上一版审查稿的历史记录。2026-08-25 更新后的清单及当前实现见 [v0.5.8 复核记录](pro-plan-v0.5.8-assessment.md)。

本记录以 2026-08-25 更新的审查稿为准。结论来自当前代码、SQLite 迁移、API 回归和浏览器流程，不把审查稿中的推测直接当成事实。

## 发布前问题

| 项目 | 结论 | 处理 |
| --- | --- | --- |
| P0-01 | 成立 | 删除按发布时间猜测状态的第二套逻辑。每个 trial 现在只有一份技师路线状态；行驶中不改道、服务中不抢占，候选状态直接用于正式续跑。trial 证据保存响应技师、派出时间、完成时间和派出位置。 |
| P0-02 | 成立 | 普通新工单保留现有路线并标为部分覆盖；新增技师保留路线并标出再优化机会；删除未分配工单保留路线。前端不再把这些响应一律当成“方案已清空”。 |

## P2 裁决

P2-01 至 P2-05 都是合理的工程改进，但不是一次稳定化提交可以安全完成的机械修改：大模块拆分会扩大回归面；OpenAPI 生成客户端需要先确定生成器和提交策略；Pyright strict 需要逐模块清债；正式 benchmark 需要稳定机器与基线；Python 双文件目前由一致性检查阻止漂移。它们保留为可执行后续项，不标记完成。

P2-06 和 P2-07 不是代码缺陷。LICENSE 会改变仓库法律授权，分支保护会改变 GitHub 治理；没有仓库所有者明确选择时不代为决定。P2-08 至 P2-10 是新的业务域（Booking、技师端、资产和库存），与审查稿自己的 v0.7 里程碑一致，不应以空模型或无流程页面冒充实现。

## 验证门槛

本轮新增时间线延迟检查点、字段影响、规划等价重新认证、父 Plan 终态竞态、比较证明降级、条件外包证据、If-Match 和损坏场景隔离回归。完整结果记录在 `task.md`；只有本机 verify 和 GitHub Actions 均通过后才视为交付完成。
