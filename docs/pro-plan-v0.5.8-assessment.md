# `pro-plan.md` 复核记录（v0.5.8）

> 这是上一版审查稿的历史记录。2026-08-25 19:49 更新后的清单及当前实现见 [v0.5.9 复核记录](pro-plan-v0.5.9-assessment.md)。

本记录对应 2026-08-25 更新的 Correctness Freeze 审查稿。结论以本地代码、迁移数据库、API 契约和可复现测试为准；旧版 [v0.5.7 复核](pro-plan-v0.5.7-assessment.md) 只保留作历史记录，不再代表当前实现。

结论分为三类：本版修复、成立但属于后续架构/产品范围、与当前产品边界不符。后续项没有被写成已经实现。

## P0

| 项目 | 裁决 | 处理 |
| --- | --- | --- |
| P0-01 | 成立 | 重写紧急响应选择。选择只读取事件时已经发生的旅行延误和确定性路线投影；选定技师后才抽取缺席、服务时长和返程延误。每个 trial 保存信息集、候选、排除原因和预计完成时间。 |
| P0-02 | 成立 | 紧急接单改用统一适用性 reducer；保留旧路线可执行性，同时把覆盖、规划和指标标为非当前，失败求解不会回滚已接收工单。 |
| P0-03 | 成立 | 公共创建 DTO 不再包含 `status`，额外字段直接 422；普通创建和紧急接单均只能生成 `pending`。状态迁移只允许走开始/完成命令。 |
| P0-04 | 成立 | 成本改为来源规则账本。`FIXED_ONLY` 在聚合前关闭新增技师工资、班次基薪和加班来源，不再从总额二次扣减；现金成本和经济影响逐项对账。 |

| P1-13 | 成立 | 新增紧急事件增量迟到、加班、未服务和受影响工单数，既能表达新阈值失败，也能表达已有失败进一步恶化。 |

| P1-16 | 成立 | CI 分别注入决策 runtime SHA 和 release SHA；纯前端/文档变动不会无理由使相同后端决策输入失去精确重试资格。 |
| P1-17 | 成立，后续 | Booking 目前已有稳定 ID、start/complete 关联和完整性检查，但尚不是独立领域实体。正式 Booking 生命周期会改变数据模型和产品流程，列入 v0.7，不用空壳表冒充完成。 |

| P1-19 | 成立 | 执行事件增加关系型技师、Plan、Booking、source-assignment 和内容哈希；所有读取及后续完成/前序判断先验证来源 Plan、payload 与 start/complete 链接。启动扫描还会报告无事件的 started/completed 状态。 |
| P1-20 | 成立，后续 | 同步求解和线程 worker 不具备持久任务租约、取消与跨进程恢复语义。v0.6 将引入持久 Job/Lease；本版不以进程内队列伪装耐久队列。 |
| P1-21 | 成立，后续 | 现有幂等接单与启动 reconcile 能避免重复接单，但不是正式 Outbox。事务 Outbox、重试和死信策略列入 v0.6。 |
| P1-22 | 成立，后续 | cooperative cancellation 不能强杀已进入 OR-Tools 的求解。独立 solver subprocess 和硬超时列入 v0.6。 |
