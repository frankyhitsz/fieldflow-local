## P2 与产品路线图

- CI 已运行 Ruff、严格 TypeScript、后端、React、构建、Demo 和 Playwright。本轮补上 TypeScript 的未使用符号及 switch 穿透门禁；ESLint 和属性测试可单独评估，不能说成当前 CI 没有类型或前端静态检查。
- 固定 seed 和确定性 Fixture 是当前验收要求。测试应避免依赖无业务意义的完整路线；现有关键断言主要检查约束、版本和 KPI。
- LICENSE 确实缺失，但许可证是所有者的法律选择，本轮不代选。
- Booking 收件箱、技师移动端、持久 worker、Outbox、库存和成本模型是合理路线图，不是当前离线调度 MVP 的缺陷。本轮先补齐正式分配约束下的开始/完成服务闭环。
