# `pro-plan.md` 第四轮复核

## 复核方法

本轮审查文件锁定提交 `f3e0a58`，文件本身没有执行仓库测试。处理时逐项沿 API、SQLite 事务、Verifier、调度器和前端状态流复核，并用回归测试验证高风险结论。下表中的“延期”表示建议合理，但需要新的业务模型或后台执行架构，不能用占位目录冒充完成。

## P0 与 P1

| 项目 | 结论 | 处理结果 |
| --- | --- | --- |
| P0-01 实验绕过执行冻结 | 成立 | 存在非 `pending` 工单时禁止创建或发布普通策略实验；发布事务仍会复核当前执行上下文。 |
| P0-02 实际开始未进入容量 | 成立 | 执行上下文保存实际开始、预计可用时间和实际完成位置；重排、标准化与验证均从该位置和时间继续。 |
| P0-03 乱序或并行开始 | 成立 | 开始服务必须等待同路线前序完成并满足实际行程时间；同一技师同一时刻只能有一个服务中工单。暂不提供绕序审批。 |
| P0-04 Reset、Rollback、Clone 与执行事件冲突 | 成立 | 有执行事件的场景禁止 Reset；Rollback 不能重新打开已开始/已完成工单或删除有事件的工单；Clone 明确生成不携带事件的规划副本，并把执行状态归一为 `pending`。 |
| P0-05 编辑清空执行依据 | 成立 | 只要已有执行状态，业务编辑保留当前 V 并将其标为数据过期；前端继续展示该执行依据，工单仍可完成。 |
| P1-01 已完成工单混入未来计划 | 成立 | 已完成工单保留在执行事件中，不再合并进未来重排 assignments。 |
| P1-02 计划指标冒充实绩 | 成立 | UI、报告和文档统一使用“计划覆盖率”“计划 SLA 达成率”“计划占用利用率”。字段名为兼容旧 API 暂不破坏性改名。 |
| P1-03 D 同时承担输入版本和事件水位 | 成立 | 新增独立、单调的执行事件序号，PlanningContext 同时绑定 D 与执行水位。D 仍作为聚合修订号保留，彻底拆成两个聚合需要兼容迁移，未在本轮破坏现有客户端。 |
| P1-04 Verifier 不独立验证 cutoff/冻结完整性 | 成立 | Verifier 重新读取权威执行上下文，检查事件水位、来源 V、全部 started 冻结项、额外冻结项、技师/顺序/时间及 cutoff。 |
| P1-05 求解政策指纹不完整 | 成立 | 新增 SolverPolicySnapshot，纳入 Profile 快照、权重、未分配倍率、实际 drop penalty、时限、solution limit、首解和局部搜索策略；Run、Candidate、Schedule 与发布事务核对同一指纹。 |
| P1-06 变化定义不一致 | 部分成立 | `changed`、稳定率和通知数现在都覆盖技师变化、相邻关系变化及超过 15 分钟的开始时间偏移。OR-Tools 的路线稳定惩罚仍是求解代理，文档不再把代理目标说成完全等价。 |
| P1-07 幂等请求仍重复求解 | 成立 | baseline、optimize、普通 replan 在求解前原子抢占命令；并发重复请求返回明确的处理中状态，完成后同键重放同一结果。终态命令不可被晚到写入覆盖。 |
| P1-08 幂等重放返回旧聚合 | 成立 | 执行动作重放返回当前 Scenario 与原不可变事件；突发 intake 重放不再拿当前可变工单内容反推原请求。前端优先读取当前 active V。 |
| P1-09 缺少 Outbox | 风险成立，延期 | 突发需求先独立持久化，重启后不会丢单且可重新发起求解；持久队列和 worker 是下一阶段架构，不用进程内线程伪装。 |
| P1-10 同步 HTTP 求解 | 成立，延期 | 当前最长单次时限 30 秒，Run/Candidate 可审计；要支持断线恢复和硬取消，需要 P1-09 的持久 worker。 |
| P1-11 Run 终态及实验发布原子性 | 成立 | Run 终态不可覆盖，Candidate 与 Run 原子结束；实验 winner 和正式 PlanVersion 在同一发布事务中写入。 |
| P1-12 历史 replan 稳定性参照 | 成立，延期 | 历史激活仍明确标注来源关系，但“血缘来源”和“下次稳定性基准”尚未拆为两个字段。 |
| P1-13 读取时隐式升级 | 成立 | 删除读取路径修补，改为 schema v8 一次性迁移；发生语义变化时新增 D 和 ScenarioRevision，并使旧计划过期。 |
| P1-14 跨快照 KPI 差值 | 缺陷结论不成立 | API 明确返回 `comparable=false`，界面只展示“原始数值变化”并列出数据差异，不将其渲染为策略优劣。 |
| P1-15 App 全局对象 | 部分成立 | 导入无数据库副作用，`create_app(store_override=...)` 可隔离 Store；默认应用仍用 lifespan 管理的进程级 Store/executor。多租户或多 app 同进程不在本地单机范围。 |

## 工程与产品建议

- CI 现在增加 Ruff 格式门禁；Playwright 失败时上传 trace、截图和报告。现有 TypeScript 严格检查保留。Mypy 和属性测试需要先补足类型边界及生成器设计，不能只装依赖让门禁名义存在。
- 精确路线测试仍保留少量用于固定 seed 的确定性验证；约束、版本、事务和血缘测试不依赖完整路线字符串。
- LICENSE 仍由仓库所有者选择，未擅自添加法律文本。
- Booking、资产、库存、成本、技师移动端、Outbox 和持久 worker 是合理路线图，但不是本轮离线调度 MVP 的补丁项。
- 页头服务时段和技能种类已改为从场景数据计算，不再硬编码 `08:00–18:00` 和三类技能。

验证命令和结果记录在根目录 `task.md`。
