## 其余审查项逐条结论

| 审查项 | 结论 | 处理 |
| --- | --- | --- |
| P1-01 A 无输出哈希 | 合理 | 已由 FF-1105 修复。 |
| P1-02 发布报告哈希未复核 | 合理 | 已由 FF-1106 修复，报告正文也进入不可变 Artifact。 |
| P1-03 同步接口绕过 A | 合理 | 保留兼容路由，但内部转为 A-run。 |
| P1-04 同步 A 与 202 恢复 | 一半属于当前缺陷，一半属于新运行时 | 前端已轮询和恢复 RUNNING；真正的异步 worker/Job Queue 是 FF-1120，不能在同步 FastAPI 调用上伪装。 |
| P1-05 EX_ANTE 混入当前执行观察 | 合理 | 输入改为绑定 V 的发布上下文；发布后的执行事件不改变历史 A 哈希。 |
| P1-06 build SHA 不等于完整运行环境 | 合理 | 当前仍保存代码版本、算法、build 和旅行/政策指纹；完整 runtime manifest 与依赖锁需要 v0.6.0 的运行时契约，未标成完成。 |
| P1-07 新增技师成本双计 | 合理 | `WAGE_ONLY`、`FIXED_ONLY`、`WAGE_PLUS_FIXED` 明确选择。 |
| P1-08 外包成本双计 | 合理 | `COST_POLICY` 与 `CAPACITY_POLICY` 二选一。 |
| P1-09 公平目标和评分不同 | 合理但不是补丁 | 当前两者各有版本和文档，未声称相同；统一为一种公平定义会改变求解政策和历史可比性，保留到 FF-1162/1166。 |
| P1-10 departure time 表面支持 | 指出风险合理，但当前不存在虚假能力 | 现有 Euclidean/Matrix provider 都是静态模型，departure 参数只为接口兼容且指纹明确；真正分时旅行需要 FF-1126 的稳定 Location 与时间分桶矩阵。 |
| P1-11 时间窗命名 | 合理 | 约束始终是“开始窗口”；文档和编辑器改用允许/最晚开始时间，不暗示服务必须在窗口内结束。 |
| Active Plan 两个权威来源 | 合理 | 当前读取以 `plan_applicability` 覆盖，未出现已知分叉；彻底移除 scenarios 指针是 FF-1125 的存储迁移。 |
| PlanVersion 重命名修改冻结 payload | 合理 | 展示元数据尚未拆表；FF-1125 处理。发布内容哈希不包含 label，当前重命名不会伪造排程证据。 |
| D 修订号过载 | 合理 | 三类修订需要 API、迁移和冲突语义一起变化，列入 FF-1124。 |
| 破坏性迁移 | 需区分历史决定与当前风险 | v1 旧历史清理是用户确认的一次性重建且先备份；v17 只新增约束表。显式迁移 CLI 和保留策略属于 FF-1127。 |
| Location 无稳定 ID | 合理 | 当前二维点和矩阵足以支持既定离线 MVP，但不适合分时/多站点，列入 FF-1126。 |
| 模块级 Store/worker | 合理 | 单进程 app factory 有隔离测试；多实例与持久 worker 需要 FF-1120/1123。 |
| 实验不能硬取消 | 合理 | 当前明确是 cooperative cancellation；子进程硬取消属于 FF-1121。 |
| 容量 Artifact 无界面 | 合理 | 已完成查看器。 |
| API 错误码丢失 | 合理 | `ApiError` 保存 status/code/details。 |
| 手工维护前端类型 | 合理 | 本轮同步了新增契约；OpenAPI 生成客户端属于 FF-1128，避免同时维护两套路由层。 |
| 前端/后端模块过大 | 合理 | 拆分需要独立回归窗口，列入 FF-1128；本轮没有为追求行数而移动无关代码。 |
| ESLint、正式 Benchmark | 合理 | 当前已有 Ruff、Pyright、TypeScript、属性测试和 smoke benchmark；ESLint 与正式规模/回归阈值列入 FF-1166/1182。 |
| 依赖双份维护 | 合理 | 需要选定锁文件生成政策，列入 v1.0 治理。 |
| LICENSE、分支保护 | 合理但需所有者决定 | 未擅自选择许可证或修改仓库治理；保留 FF-1180/1181。 |
